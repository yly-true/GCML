# 轻量化 Landmark GCML

仓库只有两个Python入口：

- `train.py`：建立稀疏地标图、采集随机游走buffer、训练并保存Q/V/W/G。
- `test.py`：加载模型做离散地标推理和消融测试，绝不重新训练。

所有参数都位于两个脚本顶部，不使用命令行参数。代码只依赖NumPy和Matplotlib。

## 1. 运行

```bash
conda activate tf215_gpu
pip install -r requirements.txt
python train.py
python test.py
```

训练输出：

- `gcml_model.npz`：地图、节点、动作、训练buffer、Q/V/W/G及其初始值。
- `train_loss.png`：Q/V转移误差、W方向误差和G affordance误差。

测试输出：

- `test_15_cases.png`：15组随机连续起终点下，GCML与一步CML的真实执行路线。
- `test_report.png`：候选轨迹数、rollout horizon和潜状态维数三组消融实验。

## 2. 稀疏节点与动作

地图包含16个房间。每个房间选择5个均匀分布的内部节点，同时固定保留18个通道中心。障碍后方只有一条连接的内部叶节点会被删除，通道节点永远不会删除。

连接关系不再使用“全图半径内可见就连边”，而是按房间规划：

1. 通道节点同时属于墙两侧的两个房间，保证跨房间必须经过明确的通道节点。
2. 每个房间内部先建立最小生成树，保证内部节点和所有门口连通。
3. 每个节点再连接房间内最近的2个可见邻居，提供少量冗余。
4. 不允许两个不同房间的内部节点直接跨墙或跨房间连边。

当前结果为：

```text
节点数：97
有向动作数：304
潜状态维数：128
```

每个节点是离散观测：

\[
o_i\in\mathbb R^N,
\qquad
s_i=Qo_i=Q_{:i}.
\]

每条有向边都是一个独立离散动作：

\[
a_k=(i\rightarrow j).
\]

因此：

\[
Q\in\mathbb R^{128\times97},
\quad
V\in\mathbb R^{128\times304},
\quad
W,G\in\mathbb R^{304\times128}.
\]

## 3. 随机游走buffer

训练不再直接遍历全部边。每条数据轨迹按以下方式生成：

1. 从所有节点中均匀随机选择初始节点。
2. 查询该节点的可执行出边。
3. 均匀随机选择一个动作。
4. 执行动作并进入目标节点。
5. 重复100步，形成一条轨迹。

buffer中的三个核心数组为：

```text
buffer_o     shape=(轨迹数, 100)  当前节点编号
buffer_a     shape=(轨迹数, 100)  动作编号
buffer_next  shape=(轨迹数, 100)  下一节点编号
```

程序至少采集200条轨迹。如果此时仍有节点或动作没有被访问，就继续采集，直到节点覆盖率和动作覆盖率都达到100%；最多允许500条，否则直接报错。

论文的抽象图实验使用200条随机轨迹、每条32步。本实现保留200条最低数量，并按当前实验要求把每条长度改为100步。

训练每轮从buffer随机抽取 `BATCH_TRAJECTORIES=16` 条完整轨迹，再使用其中的状态转移更新模型。因此训练数据来自随机探索，而不是每轮机械遍历全部节点或边。

## 4. 参数初始化

当前完全采用论文对抽象图实验给出的随机初始化：

\[
Q\sim\mathcal N(0,1),
\]

\[
V,W,G\sim\mathcal N(0,0.1).
\]

已经删除：

- 图拉普拉斯特征向量初始化。
- Q中心化和白化。
- 训练结束后固定Q的额外polish阶段。

论文没有要求这三项，因此不再引入这些额外处理。保存的未训练GCML使用的就是上述纯随机初值。

## 5. Q/V/W/G训练

buffer中的一次转移为：

\[
i\xrightarrow{a}j.
\]

当前状态、预测状态和实际下一状态为：

\[
s_t=Q_{:i},
\]

\[
\hat s_{t+1}=Q_{:i}+V_{:a},
\]

\[
s_{t+1}=Q_{:j}.
\]

预测误差：

\[
\delta=s_{t+1}-\hat s_{t+1}
=Q_{:j}-Q_{:i}-V_{:a}.
\]

V按论文公式(12)更新：

\[
V_{:a}\leftarrow V_{:a}+\eta_V\delta.
\]

Q按照作者代码更新下一观测列，使实际下一状态向预测靠拢：

\[
Q_{:j}\leftarrow Q_{:j}-\eta_Q\delta.
\]

W学习动作产生的局部状态变化：

\[
W_{a:}\leftarrow W_{a:}+\eta_W(Q_{:j}-Q_{:i})^T.
\]

节点i的真实affordance向量记为 \(g_i\)，从i出发的动作位置为1，其余为0。G按公式(17)更新：

\[
G\leftarrow G+\eta_G(g_i-GQ_{:i})Q_{:i}^T.
\]

同一节点或动作在一个batch中可能出现多次。代码先对这些样本的误差求平均，再执行一次对应局部更新，避免高访问频率节点得到不成比例的更新幅度。

论文默认学习率：

\[
\eta_Q=0.1,
\qquad
\eta_V=\eta_W=\eta_G=0.01.
\]

当前直接使用这些数值，训练轮数为 `EPOCHS=1000`。主模型维数为128；此外使用同一张地图、同一动作集和同一个buffer训练8、16、32、64维模型，只用于维数消融，不参与128维主模型推理。

## 6. GCML高维rollout

当前配置：

```text
ROLLOUTS = 100
ROLLOUT_HORIZON = 32
EXECUTION_HORIZON = 64
```

每个真实决策点并行生成100条候选，每条最多在128维潜空间想象32步。

目标状态：

\[
s^*=Q_{:\mathrm{goal}}.
\]

每个想象步骤执行：

\[
u_t=W(s^*-\hat s_t),
\]

\[
\hat g_t=G\hat s_t,
\]

\[
e_t=\hat g_t\odot(u_t+\epsilon_t),
\]

\[
a_t=\operatorname{WTA}(e_t),
\]

\[
\hat s_{t+1}=\hat s_t+Va_t.
\]

第一想象步使用当前真实affordance，第二步以后只使用 \(G\hat s_t\)。想象阶段不会查询真实下一节点，也不会进行图搜索。

当前实现不禁止重复动作，也不维护额外的动作黑名单：每一步都严格由 \(W\)、\(G\)、噪声和WTA产生动作。模型因此可以在想象或真实执行中回退、循环；这类失败会被64步真实执行上限如实暴露。

候选评分规则：

- 成功到达目标潜状态：按想象动作数排序，越短越好。
- 32步内未到达：只按最终潜状态残差排序。

失败轨迹评分为：

\[
J_{\mathrm{fail}}=\|\hat s_T-s^*\|_2.
\]

已经删除原来的 \(0.01T\) 长度惩罚。

选择最佳候选后只真实执行第一个动作，再读取真实新节点并重新生成100条候选。这是类似receding-horizon MPC的执行形式，但预测发生在学到的潜状态中。

## 7. 一步CML与“GCML只有1条轨迹”的区别

CML不生成多步想象轨迹。每个真实节点只计算：

\[
u=W(Q_{:\mathrm{goal}}-Q_{:\mathrm{current}}),
\]

然后在当前真实可行动作中确定性选择最大值，执行一步并读取真实新节点。

CML：

- 不使用G。
- 不加噪声。
- 不使用V预测未来状态。
- 不受rollout轨迹数量影响。

这里的“一步”不是整个任务只移动一次，而是每次只决定并真实执行一个动作：执行后观察新节点，再重复一次一步决策。因此CML最终仍会形成一条完整路线；`test_15_cases.png`中的蓝色虚线是这些真实一步动作累积出来的路线，不是一次想象出的多步轨迹。

CML不依赖候选轨迹数量，所以在“候选轨迹数”图中只画在横坐标1处的一个菱形点，不再画成横线。

`GCML trajectories=1`也不等于CML：

- CML确定性选择当前一步的最大方向分数。
- GCML即使只有1条候选，第一步仍加入随机噪声，并继续在潜空间想象到指定horizon。
- 但只有一条候选时，没有其他轨迹可供比较，所以后续想象结果无法在多个第一动作之间做选择。

因此单轨迹GCML本质上是“带噪声的一次采样”，通常会弱于多候选GCML，也不会与确定性CML完全相同。

## 8. 失败如何处理

当前已经完全删除fallback。

如果GCML在64次真实决策内没有到达目标，测试直接记录：

```text
success=False
```

可视化路线停在实际失败节点，不调用最短路补齐，也不会伪装成成功。

连续曲线模块也已经删除。图中的橙线只是连续起点、真实执行过的离散地标以及成功时连续终点之间的折线，用来观察高层决策结果，不参与规划。

## 9. 三组量化实验

`test_report.png`同时量化：

1. **候选轨迹数量**：固定潜维数128和horizon 32，在1至100条候选间取12个采样点，并显示未训练GCML；一步CML只显示为一个独立基线点。
2. **Rollout horizon**：固定潜维数128和候选数100，在1至64步之间取12个采样点。
3. **高维潜状态**：固定候选数100和horizon 32，比较8、16、32、64、128维下GCML与一步CML的成功率。

另外记录 `rollout hit`：每次真实决策生成100条候选后，被选中的候选是否在32步内满足 $\|\hat s_T-s^*\|_2<0.8$。若至少一条候选到达，评分会优先选到达者；若全部未到达，才选择最终潜状态残差最小者。`test_15_cases.png`中，GCML决策节点外的绿色空心圆表示被选rollout到达，红色叉表示未到达、仅按残差选取；标题 `Rhit=x/y` 是相应汇总。报告还给出总体到达率和到达轨迹的平均想象深度。这里的目标是 $Q_{:\mathrm{goal}}$ 对应的离散目标地标，不是图中星形连续坐标。

候选数量消融采用“共同随机数”：同一个真实决策点上，1、2、3、……条候选使用同一组随机噪声的前缀。因此增加候选数等价于在原候选集合后追加轨迹，不会因为随机流整体改变而造成不公平比较。报告还统计每次决策中到达目标的候选数量、不同第一动作数和不同完整动作序列数，用于确认100条rollout并非大量完全相同的复制。

这些实验使用相同地图、节点、动作集和同一批随机起终点。维数实验的各模型也使用相同buffer训练，尽量只改变被考察变量。默认使用30组随机任务；需要更稳定的统计时可继续增大 `test.py` 顶部的 `BENCHMARK_CASES`。

本次实测得到：

```text
节点 / 动作：97 / 304
GCML（15组可视化）：15/15
CML（15组可视化）：7/15
30组基准：GCML（100条）100%，CML 40%
维数8,16,32,64,128对应GCML成功率：20.0%, 60.0%, 86.7%, 100%, 100%
15组图中被选rollout命中目标：118/118（100%），命中候选平均深度6.9步
每次决策平均到达候选：56.1/100
每次决策平均不同第一动作 / 不同完整轨迹：4.0 / 70.5
```

降低节点密度后，图的平均最短跳数下降；128维允许97个离散状态获得更充分的表示。配合100条候选，30组基准保持100%成功。移除动作黑名单后，一步CML会如实暴露确定性循环，因此其30组成功率为40%；GCML仍可依靠多轨迹比较消除局部错误。平均70.5条不同完整轨迹和56.1条到达候选也说明采样具有实际多样性。未到达时仍按最终潜状态残差选择并重新规划。这些数值只对应当前随机种子和任务分布。

## 10. 当前测试检查

`test.py`检查：

- buffer节点覆盖率和动作覆盖率。
- Q/V转移RMSE。
- G affordance RMSE和出边恢复率。
- 推理前后Q/V/W/G逐元素不变。
- 每个真实执行动作都属于固定地标图的有效边。
- 失败任务保持失败，不使用fallback。
- 已训练GCML和纯随机初始化GCML随候选轨迹数量的成功率。
- GCML随rollout horizon变化的成功率。
- GCML与一步CML随潜状态维数变化的成功率。
- 候选数量和horizon变化时，被选rollout实际进入目标潜状态邻域的比例。
- 不同候选数量共享随机噪声前缀，保证rollout数量消融公平。
- 每次决策中到达候选、不同第一动作和不同完整轨迹的数量。
- Q/V/W/G维度与数值有限性、地标图连通性、buffer中每次状态转移与动作边的一致性。
- 18个通道节点是否都至少连接墙两侧局部结构。
- GCML/CML成功任务的平均真实执行步数。

当前地图固定，不再随机封堵通道；每组测试只改变连续起点和终点。
